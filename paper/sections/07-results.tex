\section{Results}
\label{sec:results}

\subsection{CPU implementation check}

The current local run is reported only as a software-verification milestone.
Across three source scenes and 35 fault variants per scene, the benchmark
created 105 cases containing 141 expected rule findings. The validator recovered
all expected findings without an additional finding under the registered
ground truth. The fixed whitelisted-tool implementation returned 102 cases to a
valid state and escalated the three unsupported-friction cases. Validation and
repair were sub-millisecond in this small CPU check, but those timings vary
with host load and are retained in the run report rather than treated as a
performance result.

The same implementation check compared the task-activated root with an
all-loaded root over three-zone fixtures. Task activation reduced composed
prim count by 20--25\%, rigid-body and collider count by 40--50\%, and bytes in
used USD layers by 18.0--24.5\%. These are structural consequences of the
fixture and confirm that the two composition conditions differ as intended;
they are not substitutes for RTX load-time, memory, and collision-query
measurements.

These values should not be interpreted as evidence that the method generalizes
to unseen construction scenes. The fault operators were written against the
same explicit contract as the validator, and the fixed repair implementation
had access to trusted source evidence. Their purpose is to verify rule
coverage, compound-fault accounting, audit generation, and the distinction
between safe repair and escalation before the held-out and language-model
comparisons are executed.

\subsection{Compiler fidelity}

On the three-scenario fixture suite, the IFC-to-scene compiler preserves the
source semantics exactly: component identity recall, IFC GUID accuracy,
categorical attribute accuracy, interface-relation and task-binding F1 are all
1.000, with zero position, dimension, and relative-mass deviation
(\texttt{generated/local-pipeline/reports/semantic-preservation.json}). These
are identity results on fixtures whose ground truth is generated jointly with
the IFC source; they verify that the compiler is lossless on the contract's
semantic vocabulary, and they calibrate the fault-injection results that
follow---every detection miss reported below is a property of the method under
test, not of information lost in compilation.

\subsection{Detection and repair on the frozen partition}
\label{sec:detection-repair}

\Cref{tab:detection-repair} reports the registered run over the frozen
partition of \Cref{sec:experiments} (105 cases: 9 development, 24 test, and
2 challenge faults over three scenario scenes, with test and challenge faults
evaluated on held-out geometric variants; manifest
\texttt{data/partition-manifest.json}, run \texttt{B-CPU-DETREp-0001}).
Direct conversion detects none of the scene-level construction faults: its
generic structural check cannot name a single rule finding, and it attempts no
repair. The frozen rule set with one whitelisted repair action per rule
recovers every expected finding on all 105 cases (precision and recall 1.000,
no false positives), returns 102 cases to a state equivalent to the pristine
scene (97.1\%, bootstrap 95\% CI [93.3, 100]), and escalates exactly the three
challenge cases whose friction record lacks an authoritative source
(2.9\%)---the designed behaviour, since fabricating a physical parameter would
be an unsupported repair. No repair that passed revalidation deviated from the
pristine scene (incorrect repair 0.0\%). The detection gap between the two
methods is significant on the paired cases (exact McNemar, $b$=105, $c$=0,
$p<10^{-31}$). The language-model rows were run against a frozen self-hosted
instruction model (Qwen2.5-Coder-14B-Instruct-AWQ, 5 seeds per case, 525
episodes per method, run \texttt{B-CPU-LLM-0001}). The contrast is stark. Left
unconstrained with the same scene and a prose problem report, the agent
returns a scene equivalent to the pristine one in only 32.8\% of episodes;
22.7\% of its repairs pass deterministic revalidation while deviating from the
pristine scene---invented identifiers, invented preconditions, and invented
physical values that no rule can distinguish from real ones---and it escalates
38.3\% of cases, including repairable faults, while 6.3\% of replies are
unusable outright (mostly truncation at the frozen decoding budget). The
validator-grounded agent, restricted to selecting among the same whitelisted
tools as the fixed-rule row, reaches 96.8\% valid repair versus the
deterministic 97.1\% ceiling (paired McNemar, $b$=2, $c$=0, $p=0.5$), with
zero incorrect repairs across all 525 episodes. Two qualifications apply.
First, $p=0.5$ is a non-significant difference, not evidence of equivalence:
we do not claim non-inferiority, which would require a pre-specified margin.
Second, the deterministic fixed-rule row is faster (0.31\,ms versus 1.5\,s)
and at least as accurate, so we position the deterministic contract and its
whitelist as the \emph{primary} repair method; the language-model agent is an
optional, contract-constrained invocation of the same tool registry, whose
value is that it can be grounded at all without the unsafe modes of the
free-form agent (fixed-rule vs free-form: $p=3.6\times10^{-102}$), not that it
outperforms the deterministic core.

A scale sweep over synthetic floors with 1--20 work zones (four members each)
confirms that the composition mechanism, not the fixture size, drives the
saving: the task-activated working set grows only with the global layer plus
the single active zone (15$\rightarrow$91 prims), while the all-loaded
composition grows linearly with the zone count (15$\rightarrow$205 prims); at
20 zones, task activation touches 56\% fewer prims and 55\% fewer layer bytes
(\texttt{resource\_efficiency.csv}, run \texttt{A3-CPU-RES-0001}).

\subsection{External IFC sanity check}

As a check outside the generated fixtures, we compiled the buildingSMART
IFC~4.3 ADD2 reference model \texttt{Building-Architecture.ifc} (13 elements,
2 spaces, no task entities; \texttt{data/external/}). The compiler produced an
empty task scene by design---elements without CSR property-set annotations are
skipped rather than guessed---and the validator refused readiness with two
critical findings (no mass or tolerance evidence records). Unannotated real
deliveries are therefore compilable but never silently treated as task-ready;
the CSR annotation layer is the explicit bridge, and its absence is itself a
contract finding (\texttt{generated/external-ifc/report.json}).

To check the complementary direction---that a non-fixture source can become
task-ready---we hand-authored an independent beam--plate--pin model
(\texttt{independent\_beam\_plate.ifc}), written from scratch rather than by
the fixture generator, carrying the CSR annotation layer (one work zone, one
interface with mate, tolerance, and axis, one insert task, and per-component
mass provenance). It compiled to a non-empty scene (3 components, 1
interface, 1 work zone, 1 task, 6 provenance records) and passed the contract
with zero issues (\texttt{generated/external-ifc-independent/report.json}).
The two external checks together bound the annotation layer's role: absent,
the scene is empty and refused; present and independently modeled, it
compiles and validates end-to-end.

\subsection{Readiness scores and the boundary of contract visibility}
\label{sec:readiness-link}

To test whether the contract's readiness signal predicts downstream outcomes
(hypothesis H4), each humanoid defect condition of \Cref{sec:task-outcomes}
was re-expressed as its scene-contract equivalent on the matching fixture
scenario and scored by the validator
(readiness = fraction of the 30 rules not violated). We assess the confusion
structure against the \emph{geometric-valid} outcome of
\Cref{tab:defect-decay} (the main assembly metric), not the looser reward
criterion, because the contract's job is to certify information the executor
must physically rely on. Every condition the validator flags is catastrophic
(semantic identity, task reference, construction state), and the validator
never flags a condition that is non-consequential geometrically (specificity
100\%). Its blind spot is exactly the geometric family: the 2, 5 and 10\,mm
hole-coordinate errors and the three reduced-clearance conditions all degrade
the geometric-valid outcome yet pass silently. Contract visibility therefore
ends exactly at the boundary of \emph{declared} tolerances: the validator
checks that tolerances and references exist and are well-formed, but not that
the coordinates inside them are faithful.

The condition-level confusion structure is made explicit in
\Cref{tab:readiness-confusion}. Counting each of the 13 defect conditions
once (a condition is \emph{consequential} if it significantly degrades the
paired geometric-valid outcome), the validator flags 4 conditions, all
catastrophic (TP); it passes 7 consequential conditions silently (FN); it
passes all 3 non-consequential conditions (TN); and it never raises a false
alarm (FP=0). Sensitivity is therefore 4/11 at the \emph{condition}
level---not a per-episode classification rate, which would be misleading
given the few independent conditions---and specificity is 3/3. Note the
contrast with the reward criterion, under which the 2 and 5\,mm hole errors
looked absorbed (TN): the geometric metric reveals them as consequential,
which is exactly the blind spot the new rules below are meant to close. Two
kinds of ``failure'' must be kept apart: an FN here is a \emph{task-risk}
miss (the scene runs degraded but the contract does not see it), distinct
from a \emph{source-consistency} violation (the scene is unfaithful to its
evidence yet still within the executor's tolerance), a distinction that
matters when the new rules are scored (\Cref{sec:discussion}).

We converted this blind spot into two contract rules and verified them on an
independent test set. CSR-SCN-031 requires member-relative interface
coordinates to carry an evidence record and to match it within the declared
tolerance; CSR-SCN-032 requires interface clearance to exceed the fastener
envelope by the task-required minimum. On held-out scene variants never used
during rule development (variant index 2), contract v0.3.0 passes pristine
scenes and within-tolerance (1\,mm) coordinate drift, and detects both
5\,mm evidence-breaking drift and sub-minimum clearance on every scene, while
the frozen v0.2.0 contract is confirmed blind to the same defects
(\texttt{generated/contract-v030/report.json}). The complete
loop---contract, runtime measurement of its blind spot, contract extension,
independent verification---is itself part of the method: the humanoid
benchmark serves as a calibration instrument for scene-readiness contracts.

\subsection{End-to-end traceability of representative defects}
\label{sec:traceability}

To make the chain from IFC to task outcome auditable rather than asserted,
\Cref{tab:traceability} traces two representative defects through every
pipeline stage on the \texttt{pin\_insertion} fixture, using committed
artefact identifiers. Defect~A (\texttt{mismatched\_task\_interface\_target})
is caught at validation: the interface reference closes, but the task binding
points at the wrong interface, so the deterministic task-reference rule flags
it and the executor is fatally mis-targeted. Defect~B (a 5\,mm
member-relative hole-coordinate drift) passes the v0.2.0 contract silently,
yet the executor still degrades---this is the blind spot the added rule
CSR-SCN-031 now closes. In both cases the same IFC GUID, CEWG node, composed
prim, resolved value, validation record, runtime target, and outcome are
recoverable from the ledger, so each number in the defect benchmark can be
traced back to a specific scene artefact rather than to a defect-class label.

Closing the loop on Defect~B, the correct--fault--repaired comparison of
\Cref{sec:traceability} was executed with the frozen v2c policy, one seed
partition, and the independent reward and geometric evaluators. The faulted
scene (5\,mm hole-coordinate drift) degrades the task (reward 84.0\%,
geometric-valid 22.5\%); the scene repaired by re-deriving the coordinate
from the evidence record recovers it (reward 88.5\%, geometric-valid 34.0\%),
returning reward success to the defect-free level and recovering most of the
geometric-valid loss. The runtime target of the repaired scene is the true
hole again, so the executor's recovery is attributable to the corrected
information rather than to any change of controller. This is the direct
evidence that the compile--validate--repair chain restores task outcome, not
merely that a defect class correlates with degradation.
